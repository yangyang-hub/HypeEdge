## 一、🔴 Critical

### A1. 市价单被无条件拒绝 — money 路径无法平仓/建仓
- **文件**：`crates/trading/src/execution/engine.rs:289`、`:559-563`
- **问题**：`let reference_price = intent.price.map(|p| p.inner())` — 市价单 `intent.price` 为 `None`。下方 290-311 行虽然拉取了 mid 快照，但 `snap.price` **从未赋回** `reference_price`。`build_order_wire`（559 行）对市价单 `reference_price.ok_or_else("market_price_not_available")?` → 拒绝。
- **触发场景**：`trend_follow::close_position`（trend_follow.rs:186）、`funding_arb::execute_leg`（runtime.rs:457）都提交 `OrderType::Market` → 全部被拒。trend-follow 永远平不了仓，funding-arb 两腿永远开不了。
- **修复**：`intent.order_type == Market` 时把 `snap.price` 赋给 `reference_price`（快照仅当 market 单才拉取）。注意 durable 重放路径 `execute_durable_command`（engine.rs:1194）同样受影响。
- **状态**：verified ✅（已读源码确认）

### A2. `query_order_by_cloid` 查询零地址 — 超时/丢失订单永远无法恢复
- **文件**：`crates/trading/src/execution/exchange.rs:192-214`
- **问题**：`query_order_by_cloid` 用 `self.account_address()` 构造 info 请求，而 `account_address()`（206-214）硬编码返回 `0x0000000000000000000000000000000000000000`。真实账户地址从未存入 client。
- **触发场景**：engine 的 `submit_to_exchange` 超时/传输错误解析（engine.rs:511,519）、durable command `requires_resolution`、cancel 恢复——全部走 cloid 查询 → 零地址返回 not found → 订单永久卡 `SubmitUnknown`，slot 永久 blocked。
- **修复**：把真实账户地址传入 `HyperliquidExchangeClient`（account/account_health.rs:593 已有正确做法可参考）。
- **状态**：verified ✅

### A3. 自动生成 cloid 非确定性 — 重启后重放会双重下单
- **文件**：`crates/trading/src/execution/engine.rs:239-244`、`crates/trading/src/execution/cloid.rs:17-26`
- **问题**：`intent.cloid` 为 `None` 时 engine 调用 `CloidGenerator::generate()`（内嵌当前毫秒时间戳 + 随机 8 位 hex），每次调用结果不同。幂等检查（engine.rs:259-273）只对调用方传入的稳定 cloid 生效。
- **触发场景**：trend_follow 提交 `cloid: None`（trend_follow.rs:151,191）。崩溃重启后 `working_order_cloid` 丢失，durable store 中旧订单用的是不同 cloid，`durable_get` 落空 → 重新提交重复订单（第二个市价平仓会翻转仓位）。
- **修复**：策略传确定性 cloid（持久化序列号），或对自动 cloid 用 normalized intent 的内容哈希做幂等键。
- **状态**：verified ✅

### A4. trend-follow runner 挂在私有 EventBus — 策略永不收到行情
- **文件**：`crates/trading/src/strategy/trend_follow_runtime.rs:39`、`:63`
- **问题**：`new()` 中 `let _ = event_bus;` 显式丢弃传入的 bus；`start()` 用 `Arc::new(EventBus::new(10_000))` 新建**私有 bus**。进程内无人向该 bus 发布 `CandleUpdate`/`OrderFilled`。

- **修复**：把存储的 `event_bus` 传给 `StrategyRunner::new`。
- **状态**：verified ✅

### A5. TF 配置解码静默失败回退默认参数
- **文件**：`crates/trading/src/strategy/trend_follow_runtime.rs:137-164`、`:194` vs `crates/trading/src/strategy/config_normalize.rs:180`
- **问题**：`normalize_trend_follow_config` 把每个 decimal 字段存为 `Value::String`（如 `"0.5"`）；`decode_trend_follow_config` 用 `v.get(k).and_then(|x| x.as_f64())` 读，`as_f64()` 对字符串返回 `None` → 整个 decode 返回 `Err` → factory 的 `.unwrap_or_default()` 静默换默认参数。
- **触发场景**：任何真实配置（含 `default_trend_follow_config_values()` 自身）都解码失败，策略按默认 `risk_per_trade_pct`/`max_position_pct` 交易，操作者配置被静默忽略。现有 roundtrip 测试用的另一默认（JSON number）掩盖了不兼容。
- **修复**：decoder 同时接受字符串与数值 decimal；decode 错误要上抛而非 `unwrap_or_default()`。
- **状态**：verified ✅

### A6. 翻转信号永远开不出反向仓位

### A15. kill switch 不持久化 — 重启静默清除
- **文件**：`crates/trading/src/risk/kill_switch.rs:71-76`（`restore_active`）；`crates/app/src/lib.rs:25-28`（每次 boot 新建）；`crates/domain/src/traits.rs:211`

### A16. 风控名义金额用订单自己的 limit 价 — 市价性卖单绕过杠杆/仓位上限
- **文件**：`crates/trading/src/risk/checker.rs:118-128`、`:193-209`；`crates/trading/src/execution/engine.rs:289`
- **问题**：`effective_reference_price` 优先取 `intent.price`（订单自己的 limit 价）。engine 只为 market 单拉快照，因此 limit 单的 notional = `size × limit_price`，**订单自己决定风控检查的数字**。
- **触发场景**：权益 $10k、max_leverage=5、max_position_pct=0.20。Bid $99,900，提交 SELL 50 BTC limit @$40（marketable，立即成交 ~$99,900）。风控算 `notional = 50×40 = $2,000`，两项都过 → 实际吃了 ~$5M 空头。买侧安全（高估 notional 拦得住），卖侧在 marketable 方向低估。
- **修复**：notional 用市场参考价（卖用 bid / 买用 ask），或取 `(limit, market)` 中更不利者；checker 需强制市场参考价（已 fail-closed on missing，但别信 `intent.price`）。
- **状态**：verified ✅

### A18. funding_arb 部分成交 IOC 永远被当作 unknown
- **文件**：`crates/trading/src/funding_arb/runtime.rs:496-526`
- **问题**：循环只在 `status == Filled && filled_size >= size` 时返回 settled。`status == Filled && filled_size < size` 落入 else 分支（`terminal_since = None`）一直轮询到 deadline，最后 `unknown: true`。engine 把部分成交的 IOC 持久化为 `Filled` + `filled_size`（engine.rs:624-646）。

- **修复**：IOC 单 `OrderStatus::Filled` 即视为终态（IOC 不可能再成交），或把 `Filled` 加入可 settle 状态集。
- **状态**：verified ✅（engine 持久化逻辑 + runtime 循环已对照）

### A22. `POST /api/v1/kill-switch {action:"reset"}` 是 no-op 却报成功
- **文件**：`crates/api/src/routes/risk.rs:57-66`

- **问题**：CH `l2_book` schema 为 `(ts, coin, side, level, px, sz)`（ch/ddl.sql:10-21）；`L2BookChRow` 声明 `(ts, coin, side, price, size, level)`。query 用 struct 字段名展开 → `SELECT ... price, size, level ...`，无 `price`/`size` 列，且列序不同 → `Unknown column price`。`export_all` 用 `?` 传播 → 整个导出在 l2_book 处中止。
- **修复**：struct 字段名改 `px`/`sz`、列序 `ts, coin, side, level, px, sz`；`side`（Enum8 → String/u8）一并核对。

### C7. 交易所 ingestor 可能把终态订单状态回退
- **文件**：`crates/storage/src/exchange_ingestor_store.rs:737-741`
- **问题**：`if !was_terminal || event_terminal { order.status = event_status }` 允许一个终态覆盖另一个。`TERMINAL_STATUSES` = {filled, cancelled, rejected, expired}（trading/src/account/exchange_ingestor.rs:34）。
- **触发场景**：filled 已入账后 REST 恢复返回陈旧 cancelled 快照（WS vs REST 乱序明确可能）→ `orders.status` 回退为 cancelled 且 `filled_size>0`，释放 reservation 走 released 而非 consumed，对账出现虚假 diff。
- **修复**：终态单调（filled 优先于任何后续终态），或按 revision/事件时间戳门控覆盖。

### C8. `DedupFilter` 死代码；clickhouse 无去重
- **文件**：`crates/storage/src/dedup.rs`、`crates/storage/src/lib.rs:31`、`crates/storage/src/clickhouse_writer.rs`
- **问题**：`DedupFilter` 导出但 writer 从不引用（grep 确认）。CH 表普通 MergeTree，事件重投/spool 重放产生重复行。
- **修复**：`enqueue` 接入 DedupFilter（键 `table+tid/ts+coin+px+sz`），或 MergeTree → ReplacingMergeTree。

### C9. 无优雅停机（SIGINT/SIGTERM 直接杀）
- **文件**：`crates/app/src/lib.rs:52-63`、`crates/app/src/main.rs:44-100`
- **问题**：`axum::serve(...).await` 无 `tokio::signal` 处理。对交易系统，重启会留下未跟踪的挂单、outbox 未 flush。
- **修复**：监听 SIGINT/SIGTERM，先撤单/停策略/刷 outbox 再退出。

### C10. `AppSettings` 派生 `Debug` 可泄漏 agent 私钥
- **文件**：`crates/config/src/settings.rs:53-78`、`:523`
- **问题**：`ExchangeSettings`（含 `agent_private_key`）派生 `Debug`，打印明文。当前无调用点直接 `?settings` 打日志（潜在），但任何未来的 `tracing::debug!(?settings)` 会把签名私钥写进结构化日志。
- **修复**：手写 `Debug` 对 `agent_private_key` 脱敏（如 `<redacted>` 或末 4 位）。
